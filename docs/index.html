Three entry points

Detection meets you where the code is written.

Existing clone-detection tools operate as a batch scan over a codebase that already exists. CloneGuard is built around closing that timing gap specifically.

01 — Real-Time Paste

Catches it as you type

A warning appears the moment a pasted method matches something already in the file — exact, renamed, near-miss, or semantically equivalent. View the original, refactor immediately, or dismiss it.

02 — File Scan

Check a whole file at once

Tools → CloneGuard → Scan Current File compares every method against every other, surfacing results with a recommended fix and tracking each session on the Trend Dashboard.

03 — GitHub PR Agent

Reviews every Pull Request

A GitHub Action scans every changed Java file automatically, posting detected clones as a checklist comment — check a box, comment /refactor, and the fix commits itself.

Automated Refactoring

A confirmed clone doesn't stop at a warning.

Four techniques, chosen automatically based on where the duplicate actually lives — and a safety check that independently re-verifies a fix immediately before applying it, rather than trusting detection blindly.

Extract Method
Type 1–3 clones within the same class — shared logic moves into one method both callers use.
Method Delegation
Type 4 semantic clones — the duplicate calls the original directly instead of re-implementing it.
Pull Up Method
Identical methods duplicated across sibling subclasses move onto their shared superclass.
Push Down Method
A superclass method used by only one subclass moves down to where it's actually used.
